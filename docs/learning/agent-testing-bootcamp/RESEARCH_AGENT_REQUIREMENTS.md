# 开放品类研究 Agent：需求与一期实施草案

更新：2026-10-19。状态：板块 1–3 的范围、原 Agent 接线与研究数据契约已实现；见 [范围模块](RESEARCH_SCOPE.md)、[接线说明](RESEARCH_INTEGRATION.md)、[数据说明](RESEARCH_DATA.md) 与 [数据测试报告](RESEARCH_DATA_TEST_REPORT.md)。自动发现、真实证据采集／价格核实、预算编排、交付和研究面板仍待开发。专用 Agent 入口、每次明确填写运行限制、新普通文字重新确认是已确认的产品选择。

后续已完成少量真实原能力观察，见 [首轮基线报告](BASELINE_REPORT.md)。手机价格补证未成功，笔记本研究人工中止；这些结果不代表新业务验收通过，默认预算也尚未校准。

## 1. 用户已经确认的需求

| 项目 | 已确认内容 |
| --- | --- |
| 用途 | 支持消费者选购和市场／竞品分析，一期优先消费者 |
| 品类 | 开放品类，不写死手机、电脑或产品名单；也支持指定产品研究 |
| 交互 | 先确认研究范围，再自动研究与交付，不要求用户逐阶段批准 |
| 推荐结果 | 按不同需求给出候选产品，说明推荐理由、取舍和不适合谁；提供对比表与证据 |
| 数据来源 | 官方资料、独立评测、公开电商价格和用户评价；注明时间、版本和来源，无法获取时说明 |
| 当前价格补证 | 用户补充确认：主动查询官网或京东等销售平台的当前价格；这些渠道都可作为来源，并非只接受官网。仍无法核实才标注“当前价格未核实” |
| 默认市场 | 中国大陆、人民币、中文报告；每次确认范围时允许修改 |
| 展示 | 增加研究面板，集中展示对象、维度、进度和可追溯证据 |
| 下载 | Markdown 研究报告与 CSV 产品对比表，报告包含来源引用 |
| 资料不足 | 在约定时间和调用预算内补证，再交付已有结果、标明缺口；证据不足不强行推荐 |
| 预算 | 先用小规模真实任务测量耗时与 token，再确定可配置默认上限；正式研究前展示限制 |
| 开发方式 | 沿用 DeerFlow 原链路，小步带练，由用户实现、测试和排错，兼顾两个岗位面试 |

消费者流程先形成完整验收标准。市场／竞品分析保留为已确认的另一用途，其专属交付物与验收规则仍待细化，不能声称消费者报告已满足市场分析要求。

## 2. 一期业务边界与验收规则草案

1. 宽泛输入应形成可确认的研究范围：购买目的、预算口径、地区与币种、偏好与硬约束、研究深度、候选规模、时间／调用限制。已有信息不重复询问；缺失的关键条件不能暗自补成用户决定。
2. 候选数量在具体任务中约定。若证据充分的候选不足，应交代原因，不能为凑数量编造产品或参数。首批用手机与电脑验证跨品类能力，不将样例当作品类白名单。
3. 比较维度由品类和用户用途共同决定；例如手机关注影像与续航，编程笔记本关注内存、接口、重量与续航。可比较事实、主观评价和模型推断分别呈现。
4. 研究前展示范围与限制，明确“确认后开始”。普通资料缺失按既定降级规则自动处理；用户主动修改关键范围时重新确认，旧条件下的结果不能直接冒充新研究结果。
5. 每个影响推荐的关键事实应关联证据。来源记录至少包含 URL、标题、来源类型、采集时间、支持该事实的摘录及对应产品版本；发布时间在可获得时记录，不能用采集时间冒充发布时间。
6. 价格必须对应地区、币种、渠道、采集时间、型号配置及可见优惠条件。用户已确认需要主动查询官网或京东等销售平台的当前价格，官网与电商均可作为来源；不能只查到旧发布稿就停止补证。记录具体店铺／卖家身份，优先官方销售渠道或平台自营；来源只展示建议零售价时应保留该口径，不能直接写成可成交的到手价。不能混用首发价、促销价、会员价、补贴价、二手价。针对具体配置，在约定预算内尝试查询销售渠道后仍无法确认，才标注“当前价格未核实”，并记录访问失败、配置不明、价格条件不完整或预算结束等原因；不猜测折扣，不用 0 代替未知。搜索摘要只能作为查找线索，不能独自证明当前可购买价格。
7. 官方参数、评测结果和用户评价适用于不同事实。性能／体验结论保留评测条件；少量公开评价不能被描述为总体用户满意度。相互转载不算独立交叉验证。
8. 来源冲突要保留不同说法并说明口径，不能悄悄选取有利数值。链接能打开与来源支持结论是两项独立检查。
9. 正常完成、部分完成、证据不足、用户取消与系统失败应在业务展示中区分。它们不直接替换 Gateway 的 Run 状态；Run success 本身不证明选购任务完成。
10. 面板展示已确认范围、当前阶段、候选及筛选理由、对比维度、证据、缺口和下载入口。进度来自真实执行状态，不生成无依据的百分比；刷新后应恢复持久化结果。
11. 报告说明研究范围、候选发现与淘汰理由、对比结果、分需求建议、不适合谁、限制和来源。CSV 与面板使用同一份结构化结果，包含来源定位信息，避免三份内容彼此矛盾。
12. 达到上限前停止新搜索并预留交付资源；若模型或网络不可用，已有结构化事实应能生成最小报告和表格。硬停、取消、文件写入失败不得显示“完整交付”。

本轮没有将 PDF、历史版本比较、价格监控、自动购买、登录后电商采集、付费数据源或用户上传分析加入一期承诺。遇到登录要求或访问限制时记录缺口；购买渠道信息不代表实际库存或成交价保证。

## 3. 业务任务链路

输入方向与已有条件 → 补齐重要条件 → 形成范围并由用户确认 → 发现候选与规划维度 → 检索并读取来源 → 提取和归一事实 → 交叉核对与有限补证 → 按需求分析取舍 → 交付面板、Markdown 和 CSV。

2026-10-19 本轮确认：一期范围确认前不联网探索。只追问会改变研究方向的重要信息，其他内容可标记为建议后统一确认。购买预算允许明确不限，未说明不能当成不限。所有实质范围变化都重新确认，包括偏好、研究重点、报告要求和运行限制；后续可在已确认目标内细化比较维度。候选数量是目标，证据不足时可以少于目标交付并说明原因，不凑数。

模型负责提出查询、发现候选、建议维度及解释取舍。程序负责类型与范围校验、来源关联、单位与价格口径检查、预算约束、持久化和文件生成。业务完成判定结合结构化校验与证据审核，不能只询问模型“是否完成”。

下列位置已只读核对；它们证明已有基础设施，不证明研究业务已经实现。

| 层次 | 现有入口／能力 | 本项目需要补充的内容 |
| --- | --- | --- |
| 页面 | `frontend/src/components/workspace/chats/chat-page.tsx`、`core/threads/hooks.ts` 的 `useStream` / `thread.submit` | 研究范围确认与面板，复用聊天发送和已有输入卡 |
| Gateway | `backend/app/gateway/routers/thread_runs.py`、`services.py` 的 `start_run` / `sse_consumer` | 沿用认证与 Thread/Run 接口；新增业务接口前先确认现有状态投影是否足够 |

| 搜索与读取 | `community/ddg_search/tools.py`、`community/jina_ai/tools.py` | 先测公开来源可达性，再确定错误语义、长文读取和证据保存所需的最小补充 |
| 状态与流 | `agents/thread_state.py`、前端 `core/threads/types.ts` 和 `stream-state.ts` | 研究摘要、阶段、候选、维度与证据索引；需要同时处理增量更新和刷新恢复 |
| 文件 | 前端 `core/artifacts/`、`components/workspace/artifacts/`，已有 Markdown/CSV 预览与下载能力 | 从经过校验的研究结果生成一致的报告、CSV 和引用 |
| 观测／测试 | `backend/docs/RUN_EVENT_STREAM.md`、`REPLAY_E2E.md` | 研究任务的脱敏追踪、故障用例、录制／回放和真实模型评测 |

运行路径：聊天／面板提交 → Next.js 本地代理 → Gateway 创建 Run → Runtime 装配原主 Agent → 模型与工具循环 → 状态和产物持久化 → StreamBridge/SSE → 聊天与研究面板；刷新从持久化状态和文件恢复。

### 已发现的限制

- 搜索 `_search_text` 遇到依赖缺失或检索异常会返回 `[]`，上层也将空结果呈现为 `No results found`。新业务不能据此断言市场上不存在产品。是否局部增加结果契约还是修正共享工具，要先用失败用例确定必要改动。
- 现有 `web_fetch` 返回正文 Markdown 的前 4096 个字符。证据可能在截断之后；方法论要求“读取全文”不等于工具真的返回全文。需要先测实际来源，不默认扩大所有共享工具输出。
- 板块 2 已增加服务端 `ThreadState.research`，板块 3 增加阶段和有界结果索引；前端 `stream-state.ts` 目前显式处理 `title/artifacts/todos/goal`。后端字段与现有 SSE 不自动形成研究面板，该界面仍待板块 8。
- 已有 token 预算中间件基于模型响应后的用量触发警告／剥离工具调用；不是严格的请求前计费上限，也不保证报告文件生成。需单独设计研究停止条件与交付预留，记录单次模型请求可能造成的超出。
- 已有确认卡和 Run 取消能力仍需研究场景回归。需求调研阶段没有调用模型；后续基线已观察确认卡、官网／电商读取尝试和一次页面取消，具体结果及未验证边界见基线报告。

### 最小实现方向（建议，非已冻结接口）

优先一个研究业务模块、原聊天内一个研究面板、已有 Thread 持久化与文件能力；先不引入新服务、数据库产品、消息队列或强制多 Agent 编排。

数据至少要表达：研究范围及确认版本、候选产品及配置、比较维度、事实及单位／口径、来源及摘录、事实与来源关联、建议及依据、缺口、阶段与消耗、产物路径。它们是概念关系，不代表需要同等数量的数据库表或类。

建议 ThreadState 保存有界的面板摘要与索引，较长来源材料留在线程目录，服务端验证写入与归属。具体字段、合并策略、文件格式和是否需要专门读取端点，在首个带练模块中用测试确定；不要无条件把完整网页正文塞入状态。按研究标识关联确认前后不同 Run，不能假设整项研究永远只有一个 Run。后续研究的产物不得覆盖或混入前一项研究。

## 5. 业务验收样例草案

以下输入用于讨论验收，不是用户真实采购请求，也没有开展联网研究。候选名称与正确结论由冻结来源样本／当次实时证据确定，不事先编造。

### A. 宽泛手机选购

输入：“我想买手机。”

预期：不直接给排行榜；确认预算、用途和关键偏好，展示中国大陆／人民币／中文默认值及限制。用户进一步提供“预算 3000–4000 元，日常拍照和续航优先，不玩大型游戏，比较 4 款全新手机”并确认后，自动发现候选、规划维度和收集证据。

验收：符合预算与市场口径；区分具体存储版本；参数、价格与体验评价有对应来源；按影像、续航等需求解释取舍与不适合谁；公开电商信息获取失败要显示缺口；不足 4 款时说明原因而不凑数；面板与文件一致。

### B. 跨品类编程笔记本

输入：“预算 6000–8000 元，买电脑用于 Python 开发、Docker 和日常携带，不考虑二手，比较 3 款。”

预期：将日常携带纳入范围，并确认操作系统、便携要求等重要条件；能从已有输入判断的内容不重复询问。维度应适应该用途，而不是沿用手机模板；分清 CPU、内存、存储和机型配置，不能拿高配评测支持低配购买建议。

验收：相同的一套研究关系能承载另一品类；推荐满足确认后的硬约束；性能与续航引用说明测试条件；缺失重量或价格不能填写虚构值。样例中的 Docker 是购买用途，不是在本机启动 Docker 构建的指令。

### C. 证据不足与部分交付

使用受控来源样本模拟：一个链接超时、一个价格过期、两个来源口径冲突；随后模拟研究预算耗尽。

验收：有限重试后停止；未知不变成 0；冲突不被静默覆盖；保留已验证事实与缺口，交付部分报告和 CSV；证据不足时不作确定性购买推荐；取消与文件生成失败分别呈现真实状态。

当前价格回归样例：检索先返回一篇旧发布稿，Agent 应继续查官网或京东等销售平台。若找到匹配配置的当前价格，须保留渠道、采集时间、价格口径与优惠条件；若只找到不同配置、历史价格、含糊的补贴价格，或公开销售页面不可访问，则不得填写确定的当前到手价，应标注“当前价格未核实”及原因。旧型号的固定规格可以继续引用历史资料，当前价格单独补证。

## 6. 测试与 Agent 评测方案草案

| 层次 | 验证内容 | 证据与边界 |
| --- | --- | --- |
| 确定性业务测试 | 范围与确认、币种／配置／单位、事实来源关联、缺失／冲突、预算停止、CSV 转义与表格公式风险、产物一致性 | 固定输入与断言；后端先失败测试再最小实现，不调用真实模型 |
| 工具集成 | 无结果与故障、超时、限流、正文截断、重复页面、恶意来源指令、用户隔离 | 固定网页样本与故障注入；不将 mock 可达性当作真实站点可达性 |
| Agent 离线行为 | 确认前不开展正式研究、不越界改范围、失败后补证／停止、调用参数、有限重试 | 模型替身或受控回放验证编排契约；不能证明真实模型能自主做出同样决策 |
| HTTP/SSE | 研究状态更新、快照恢复、断流重连、重复提交、取消、鉴权和跨用户访问 | 复用真实 Gateway 回放与契约检查；新增事件时同步运行事件契约 |
| UI | 范围确认、面板切换、证据定位、部分完成、下载、刷新恢复、空态／错误态 | 组件测试与浏览器端到端；至少一条真实前后端链路，不能全部依赖手写 SSE mock |
| 真实模型评测 | 候选相关性、约束满足、维度适用性、事实准确性、引用支持性、建议实用性、缺口披露 | 使用现有 DeepSeek，小批任务逐项人工核对，再扩充评测集 |
| 稳定性／性能 | 单阶段与总耗时、模型调用／工具调用／重试次数、输入输出 token、部分交付与失败率 | 固定配置并重复运行，报告样本数和范围；少量结果不作稳定性或 p95 承诺 |

真实模型集应覆盖宽泛／明确输入、指定产品、不同品类、不同地区、预算与偏好冲突、资料缺失与冲突、工具故障、预算结束、提示注入等类别。先做小批校准，再确定正式集合规模；本轮没有承诺“20 条已通过”。

确定性规则检查结构与硬约束；人工检查引用原文是否支持事实、比较口径是否合理、建议是否符合需求；模型评价可辅助整理，需用人工标注校准，不能由同一模型自评作为唯一通过依据。

优先列出不能靠其他高分抵消的严重问题：虚构关键事实／来源、混用配置导致错误推荐、未确认即开始正式研究、隐瞒关键缺口、越权读取。其余质量指标先分别报告数量、分母与错误示例，不武断设置综合权重或总分阈值。检索召回只针对有明确候选范围的标注样本，不能声称全网召回率。

基线实验记录模型与参数、提示词／技能与代码版本、任务输入和确认范围、来源时间、调用轨迹、耗时、token、产物与人工核对结果；无法获得供应商计费单价时不编造费用。研究前探索和确认后的正式运行分项记录，并给出总量；包含有开销的后台活动时单独注明，避免漏计或混计。

## 7. 带练与实施顺序
