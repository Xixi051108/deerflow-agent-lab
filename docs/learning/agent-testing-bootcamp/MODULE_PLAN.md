## 起点与工作方式

- **原能力基线已经完成观察，不再作为待办。** 手机研究当前价格证据不足；明确补证后仍未核实；笔记本研究由助手人工停止，后台 interrupted，53 次汇总模型调用、约 141 万 tokens，无报告和 CSV。人工中止不是自主停止，10 分钟不是产品默认上限。
- **现在直接开发消费者选购研究功能。** 沿用聊天 → Gateway → 原 Agent → 工具 → 状态／产物 → SSE／页面，不另建服务或 Agent 循环，不恢复 T1007 等旧练习。
- **按完整板块带练。** 助手先发整块任务书，说明要解决的问题、链路位置、要开发的功能与验收；用户连续实现、测试和排错，不要求每写几行就停下来。板块完成后集中讲注意事项、设计取舍、失败原因与双岗位面试追问；卡住时随时给提示。
- 后端在板块内逐项执行先失败测试、再实现、再验证；测试和面试复盘贯穿全部开发，不拖到最后。代码简单、改动聚焦是工程原则，不是把教学拆碎的理由。
- 表内是学习／开发板块，不要求一块对应一个类、服务或数据库表。具体字段、工具名与写入接口在相应板块开始时结合代码确定。

## 各板块任务与退出条件

### 1. 研究范围校验与确认约束

- **开发／交付：** `deerflow.agents.research.scope` 已提供范围模型、完整性检查、确认请求／回答、整份范围替换和准入检查。接口与完整示例见 [范围模块说明](RESEARCH_SCOPE.md)。
- **规则：** 允许不完整草案；只追问重要缺口；购买预算允许明确不限；默认建议可见；确认前不联网。确认绑定研究标识、范围版本、请求标识和完整快照；所有实质变化重新确认，过期回答拒绝，同一有效回答幂等。
- **验收：** 覆盖对象发现／指定名单、预算与运行限制、歧义、完整性、确认、变更、不可变性及 JSON 恢复。运行限制仅声明，实际停止规则后续实现；自然语言歧义不由通用规则引擎判断。
- **实际验证：** 前两轮测试复现模块缺失和候选边界漏查，修复后得到 `2 passed`，随后补齐剩余规则、测试与报告。
- **集中复盘：** Agent 岗问“为什么提示词不能代替约束”；测试岗问“无效等价类、边界和状态迁移如何覆盖”。纯规则测试通过不代表真实链路已拦截，接线由板块 2 验证。

### 2. 原 Agent 链路接入与状态持久化

**实际交付：** 专用 Agent 配置、服务端研究状态、当前操作校验、原确认卡、同步／异步工具拦截、full／delta SQLite 恢复、HTTP/SSE／事件历史、回放与分支隔离已接入。每次明确运行限制，所有新普通文字触发重新确认。随后数据与证据契约已在板块 3 交付，不重做入门基线。

- **开发：** 将范围和对应确认信息存入 ThreadState；消费现有确认卡的回答，校验后更新范围；在研究模式的实际执行路径使用板块 1 的准入检查。
- **交付：** 同一个 Thread 内，提出范围、用户确认、正式研究可以跨 Run 衔接；关联当前研究和确认请求，旧回答不能确认新范围，后续研究不能混用上一项研究的数据。
- **验收：** 模型替身故意跳过确认并发出研究动作时，动作不执行；确认后可执行；改条件后再次阻止；普通澄清 Run 仍可创建。检查持久化恢复与研究之间的隔离。
- **集中复盘：** Agent 岗问“Thread、Run、State 与确认版本如何关联”；测试岗问“纯规则绿了，为什么还要真实图接线测试”。优先参考现有图集成测试，不重写运行框架。

### 3. 研究数据与证据契约

**实际交付：** 开放品类契约、配置／来源／引用校验、事实／评价／推断分离、Decimal 与未知值、缺口和冲突、受校验批次写入与分页读取、不可变快照和有界状态索引。沿用原 Agent 权限链、HTTP/SSE 与 full／delta checkpoint；新范围、研究、历史恢复及分支不继承旧结果指针。来源标签和真实 Windows junction 问题有失败复现与修复回归，详见本块说明和报告。下一步是板块 4，不开展无上限真实研究。

- **开发：** 增加产品及具体配置、比较维度、事实及单位、来源及摘录、事实与来源关联、缺口和研究阶段的数据表达与写入校验。复用线程持久化和文件目录，状态保存有界摘要／索引。
- **交付：** 后续采集、分析、面板与文件使用同一份研究结果，区分事实、评价与推断；缺失值可明确表达，不用 0 或空字符串伪装已知事实。
- **验收：** 能装载手机和笔记本受控样本，拒绝悬空引用、错配研究归属等非法写入；型号配置与来源能追溯。概念关系不强制变成同等数量的表或类。
- **集中复盘：** Agent 岗问“为什么结构化结果不能只留在模型文本里”；测试岗问“契约、关联与序列化怎么测”。

### 4. 候选发现与比较维度规划

完整任务、代码入口、拟定数据增量、开发顺序与验收矩阵见 [板块四实施任务书](RESEARCH_DISCOVERY_PLAN.md)。沿用原中间件和数据工具，开发时先失败测试，再接入指引与保存前范围检查；不提前开展无预算真实研究。

**实际交付：** 原中间件静态发现指引、保存前合并结果的数量／名单／排除／去重校验、候选来源与用户名称绑定、新写入理由和维度口径检查、旧快照原哈希兼容。新增离线 54 项、严格 I/O 2 项和 opt-in 实模 3 项。真实 DeepSeek 使用固定检索资料、每例独立调用与超时保护，未调用真实网站或实施业务预算；不能用结构断言通过代替回答质量，已将实际发现的两类语义错误纳入检查。

- **开发：** 在原 Agent 配置、研究指引和工具路径中接入发现候选、记录筛选理由与规划比较维度的行为，写入板块 3 的数据；支持宽泛品类和用户指定产品。
- **交付：** 品类与产品名单不写死，候选数量来自当次确认；比较维度随用途变化，例如影像／续航与编程／携带采用不同维度。
- **验收：** 先用受控检索样本和模型替身验证写入、筛选及越界限制；候选不足说明原因，不凑数、不擅自改变硬约束。此时不运行无上限的真实自主研究。
- **集中复盘：** Agent 岗问“模型决定什么、程序验证什么”；测试岗问“开放网络没有完整答案时如何评价候选，为什么不能宣称全网召回率”。

### 5. 证据采集、当前价格与事实核对

完整目标、开发顺序与E01–E22验收矩阵见 [板块五实施任务书](RESEARCH_EVIDENCE_PLAN.md)；实际接口与覆盖边界见 [实现说明](RESEARCH_EVIDENCE.md) 和 [测试报告](RESEARCH_EVIDENCE_TEST_REPORT.md)。已调整板块四“只写规划集合”的指引，先规划再采集；预算收束、报告与面板仍分别归板块6–8。

- **开发：** 复用现有搜索与读取工具，接入结构化证据保存；针对来源故障、正文截断、配置匹配、单位／价格口径和来源冲突，补齐研究所需处理。
- **交付：** 关键事实包含来源 URL、标题、类型、采集时间、支持摘录与适用配置；主动尝试官网、京东等销售渠道获取当前价格，记录店铺／卖家及优惠条件。
- **验收：** 固定样本覆盖旧发布稿、不同配置、会员／补贴条件不明、访问失败、截断与冲突。旧发布稿不能证明当前到手价；补证仍无法核实时明确未知及原因；搜索摘要不能单独证明当前可购买价格。
- **集中复盘：** Agent 岗问“怎样避免错误引用和价格幻觉”；测试岗问“链接有效与内容支持结论怎样分别验证”。不预设访问失败根因，不增加登录后采集承诺。

### 6. 研究编排、预算与异常收束

- **开发：** 沿用原 Agent 循环，接入研究阶段、研究前展示的运行限制、有限重试／补证、停止新检索与交付资源预留；区分完整、部分、证据不足、取消和系统失败。
- **交付：** 数据不足时有明确收束路径，保留已有事实与缺口；模型或网络不可用时，结构化数据仍可交给报告生成逻辑。与板块 7 联调完成部分交付。
- **验收：** 用固定响应、时钟和工具故障复现重复查询、预算结束、超时、取消及写入失败；达到规则限制后不继续新增检索。单次请求可能超出事后 token 统计阈值时如实记录，不声称已有精确请求前计费上限。
- **集中复盘：** Agent 岗问“谁控制停止，为什么模型说完成还不够”；测试岗问“如何确定性测试重试、时间与取消”。默认数值在板块 9 受控校准，不照搬基线人工停止的 10 分钟。

### 7. 分析推荐与报告交付

- **开发：** 基于已核对事实给出分需求建议、推荐理由、取舍与不适合谁；从同一结构化结果生成带引用 Markdown 报告和 CSV，接入现有 artifacts 展示／下载机制。
- **交付：** 报告说明范围、候选与淘汰理由、比较结果、建议、限制和来源；证据不足不强行推荐，部分结果仍可交付。
- **验收：** 面向固定事实样本检查引用、缺失值、CSV 转义／表格公式风险、两类文件内容一致；模型不可用时可生成最小报告；文件失败与用户取消不得显示完整交付。
- **集中复盘：** Agent 岗问“分析与事实如何分开，为什么文件生成由程序保证”；测试岗问“怎样判断报告正确，如何测试产物一致性”。

### 8. 研究面板与前后端交互

- **开发：** 在原聊天内增加面板，展示已确认范围、真实阶段、候选与理由、维度、证据、缺口和下载；补前端类型与流状态处理，接入持久化快照恢复。
- **交付：** 用户能确认／修改范围、查看证据、下载报告和 CSV，刷新后恢复研究信息；进度来自执行状态，不编造百分比。
- **验收：** 组件与浏览器用例覆盖确认、变更失效、刷新、空态、错误、部分完成和取消；检查 HTTP/SSE、断流恢复与跨用户隔离；至少一条真实前后端连接，不能全部用手写 SSE mock 证明接线。
- **集中复盘：** Agent 岗问“状态如何从工具到面板”；测试岗问“接口、组件、端到端各证明什么，怎样避免定位与时序造成的不稳定测试”。

### 9. 改造后系统回归、评测与成本校准

- **开发／验证：** 汇总各块用例，复用现有测试、回放和 CI 机制，补新功能回归集、评测记录与结果汇总；不另起重复测试平台。
- **交付：** 固定用例、改造后的运行配置／版本、分项结果、失败证据与修复回归。板块 4 已提前做受控固定资料的真实模型验证；待板块 6、7 的收束和交付可靠后，再用已有 DeepSeek 做有明确上限的开放网络闭环验证，校准默认预算。
- **验收：** 覆盖宽泛／明确输入、指定产品、跨品类、范围变更、价格与配置、故障、提示注入、隔离、取消和交付；区分确定性测试、模型替身编排、真实模型质量和人工引用审核的证据。
- **集中复盘：** Agent 岗问“怎样评测 Agent 与分解 token 消耗”；测试岗问“通过率分母、回归范围、严重错误和性能样本如何定义”。不重复昨天的无约束高消耗基线，不先定综合分数、样本量或 p95 承诺；记录后端已知 Windows 失败，不声称全量绿。

### 10. 项目复盘、演示与双岗位面试

- **整理：** 每块积累本人实现、助手提示、测试、故障与独立解释；最后串联消费者选购演示、架构说明、需求变更与缺陷闭环，整理两方向项目介绍和简历证据。
- **交付：** 演示步骤、本人贡献说明、开发／测试两版项目表达；已有证据、待补实验与专项基础知识分开记录。
- **验收：** 用户能闭卷解释一次完整链路、一个设计取舍和一个实际失败修复；按新面试题查缺补漏，不虚构个人贡献、优化比例、线上事故或生产规模。
