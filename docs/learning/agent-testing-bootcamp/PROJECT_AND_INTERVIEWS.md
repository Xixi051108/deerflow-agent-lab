# 竞品研究项目与双岗位面试准备

更新：2026-10-19。板块 1–3 的范围、接线及研究数据契约已实现，研究业务尚未完整；具体顺序执行 [10 个二次开发板块计划](MODULE_PLAN.md)，最新说明与验证证据见 [研究数据](RESEARCH_DATA.md) 和 [测试报告](RESEARCH_DATA_TEST_REPORT.md)。

## 已确定的项目方向

在 DeerFlow 原有聊天、Gateway、Agent、工具与文件产物链路中，开发支持开放品类输入的市场与竞品研究 Agent。用户可以输入“手机”“电脑”等方向，由 Agent 发现研究对象、规划比较维度、采集证据、分析并交付报告，也可以指定产品继续研究。

不把品类或产品名单写死。首轮用手机、电脑两个不同品类设计验收样例，不据此宣称已验证所有品类。用户已确认两种用途都支持，一期优先消费者选购；先确认范围再自动研究，增加研究面板，并交付带引用的 Markdown 报告与 CSV 对比表。默认中国大陆、人民币、中文，可在每次确认范围时修改。覆盖官方、独立评测和公开电商资料，预算内有限补证、缺口明确披露、证据不足不强行推荐；默认预算先以真实小批任务校准。已确认需求、业务与系统链路、验收和测试草案见 [研究 Agent 需求](RESEARCH_AGENT_REQUIREMENTS.md)。范围接口已实现，研究链路与市场分析专属验收仍待细化。

用户同时准备 Agent 应用开发、测试开发实习，两条路线同等重要。主线是有完整业务交付的二次开发；此前合成任务诊断工具属于链路与测试学习样例。暂停 T1007 取消任务与按状态查询任务的练习，不自动将它们继续扩展成主项目。

## 带练与验收方式

每个核心模块都留下五类说明：要解决的业务问题、方案与取舍、实际实现、测试和失败证据、可独立解释的复盘。

按完整板块布置任务，用户可连续完成实现、测试和排错，完成后集中讲注意事项、取舍及面试题；不把交流切成每几行代码等待一次。TDD 仍在板块内逐项执行，测试与面试准备贯穿开发。板块 1–8 实际开发业务功能，9 验证改造后闭环与校准成本，10 集中整理求职证据；不重跑已有高消耗基线。

面试准备贯穿开发。用户会在项目结束时补充面试题，届时按“已有实践证据／需要补做实验／需要专项学习”分类补齐，不只准备现有截图中的题目，也不为覆盖题目堆砌功能。

## 面试回答与新题补齐

一题至少包含：实际场景 → 自己做了什么 → 为什么这样选 → 如何验证 → 结果与限制。没有实际数据时标记“待实验”，不虚构提升比例、稳定性结论、用户规模或线上事故。

后续面试题记录格式：题目、对应模块、当前回答、证据位置、缺口、补做动作、复测或闭卷复述结果。后续题目可以扩展这张地图，不局限于截图的第 2–29 题。

GIL、线程／进程／协程底层原理、算法与复杂度另设专项练习；项目中的使用经验不能代替基础知识。原生 App、滑动验证码、定位自修复等按实际需要决定是否实践，不承诺项目天然覆盖所有技术点。
