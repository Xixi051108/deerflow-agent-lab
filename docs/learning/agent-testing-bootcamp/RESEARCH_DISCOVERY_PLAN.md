# 板块四实施计划：候选发现与比较维度规划

日期：2026-10-20。本文件保留本块任务设计；现已实施，实际行为见 [实现说明](RESEARCH_DISCOVERY.md)，实际结果与全量限制见 [测试报告](RESEARCH_DISCOVERY_TEST_REPORT.md)，不以计划验收项代替执行结果。对应 [10 个板块计划](MODULE_PLAN.md) 的板块 4，不是需求文档中历史五阶段草案的“研究面板”。代码核对基点：`main`，HEAD `0a8d5db`；规划前仅有未跟踪的 `.extensions_config.json.lock`，保持原样。

## 1. 本块目标与交付边界

在 DeerFlow 原研究 Agent 内，使“确认后的研究范围”形成可持久化的候选与比较方案：**找哪些产品、为什么入选或排除、准备比较什么、哪些条件仍缺证据。**

沿用既有产品决定：开放品类；一期优先消费者选购；支持自动发现和指定名单；候选数量来自当前确认；中国大陆／CNY／中文是可修改的可见默认值；所有新普通文字先重新确认。无需用户对候选发现、维度规划逐阶段批准；Agent 在已确认目标内细化维度不额外出卡，需要改变范围时重新提议。用户发送新文字仍遵守原重新确认规则。

本块交付：

- 与研究模式同时启用的发现／筛选／维度规划指引。
- 候选与确认名单、发现来源的可追溯关联，以及写入前的范围检查。
- 随用途变化的维度及口径，通过现有数据工具写入原快照。
- 受控手机、编程笔记本、指定名单及异常样例的规则、原图、HTTP/SSE 和恢复验证。
- 使用说明、逐用例测试报告、失败定位与双岗位复盘。

板块 5 才核实具体参数、当前销售价格与来源冲突；板块 6 才接入运行预算与阶段收束；板块 7 才交付推荐、Markdown／CSV；板块 8 才增加面板。本块的候选不是最终推荐，`candidate` 不代表价格、库存或硬条件已经核实。市场分析专属指标与交付物仍在对应业务进入实施前细化。

## 3. 预期业务流程

1. **读取当前确认范围与已有数据。** 未确认先走原确认流程；已有结果时分页读取，复用稳定 ID，不把跨 Run 的模型记忆当结果库。
2. **提出查询与维度。** 从品类、用途、地区、偏好及硬约束组织查询。仅研究指定对象时，仍可检索这些对象的资料，但不扩大比较名单。
3. **检索候选线索。** 自动发现从实际返回的公开搜索结果取产品；从用户提供或工具返回的 URL 读取页面，不凭模型记忆制造发现来源。
4. **辨别产品与配置。** 区分产品型号、内存／存储等配置和店铺页面；同一产品不同配置使用 Configuration，不用多个店铺或配置凑候选数量。别名由模型识别并记录，程序只做明确的身份和引用检查。
5. **筛选并说明。** 按当前范围保留拟比较对象、记录排除对象与原因。可疑或缺证据条件进入 Gap；不能把未知写成“已满足”。指定对象不符合条件时保留排除说明，不偷偷换型号。
6. **规划比较维度。** 解释维度为什么与本次用途相关，明确类型、单位和比较口径。用户已指定关注点／必须检查项应得到覆盖；需要改变目标或硬约束时回到范围提议。
7. **单独提交数据写入。** 一次写入只调用 `record_research_data`，携带当前研究／范围／数据版本；程序检查整份合并结果，成功后保存并更新索引。
8. **读取验证和说明缺口。** 验收最终受控快照中的候选、淘汰原因、维度和缺口。数量不足说明已检索范围与证据不足；不把它描述成全市场没有其他产品。

这里是同一个 Agent 工具循环中的业务步骤，不新增 Agent 循环、后台任务或每步审批。此时 `phase` 仍沿用 awaiting_confirmation／recording；不提前引入“研究完成”、进度百分比或预算已执行标记。

## 4. 最小实现方案

### 4.1 研究指引

建议新增 `research/planning.py`，集中放静态发现指引与纯范围检查函数，通过原中间件接入。若实现时同一文件职责不清，只做必要拆分，不引入策略注册、品类插件或通用工作流引擎。

- 静态指引随 `research_enabled` 生效，不依赖可选技能是否加载。已有配置示例的 `skills: []` 也应正常获得指引。
- 使用现有 `_inject`：可信固定规则进入系统消息，用户范围、产品名、理由和网页文本继续作为不可信数据；不拼入系统指令。
- 指引区分允许发现、仅指定对象、指定对象加自动补充三种路径；提示读取旧数据、稳定 ID、独立写入、失败与不足说明。
- 实际工具受原配置／权限控制。缺搜索或读取能力时说明缺口，不能虚构调用结果，也不自动修改工具权限。
- 不把通用主提示词改成消费者选购提示词，普通 Agent 保持原行为。

### 4.2 数据增量（拟定字段，在首轮契约测试中落实）

优先复用 Product.reason、Dimension.description／basis 和 Gap，仅增加现有字段不能可靠表达的关联：

| 信息 | 拟定表达 | 约束及用途 |
| --- | --- | --- |
| 候选对应哪个范围内原始名称 | `Product.scope_name: Text \| None = None` | 值必须来自当前 named／excluded 名单；解决用户输入简称与规范产品名不同的问题；不是身份核实凭据 |
| 自动发现线索来自哪里 | `Product.discovery_source_ids: tuple[Id, ...] = ()` | 关联已有 Source；必须属于该产品，不能悬空、跨产品或重复；保留 URL、标题、采集时间与实际返回文本 |
| 入选／排除理由 | 复用 `Product.reason` | 新增或更新的候选均须有非空理由；解释与用途或条件的关系，不承诺事实已核实 |
| 维度适用理由与口径 | 复用 `Dimension.description`、`basis`、`kind`、`unit` | 新增／更新维度说明为何比较、如何比较；不增加固定手机／电脑字段 |
| 候选不足或硬条件未核实 | 复用 Gap | 可挂研究、产品、配置或维度；缺口要说明原因和影响，不用空值冒充已确认 |

新可选字段保留默认值，旧 schema_version=1 快照应继续可读；新增范围检查不放入加载旧文件的通用模型验证器。旧文件不重写、不重新计算文件哈希、不批量迁移。对本次新增／更新产品和维度执行理由与来源要求；合并结果涉及的名单和数量检查仍须覆盖已有记录。旧结果不满足新写入规则时给出明确修正错误，不能静默删除或扩大范围。

自动发现候选至少关联一条可用发现来源；用户指定名称可先作为待核实对象保存，不假造来源。搜索摘要只可作发现线索：Source 用实际返回文本，`kind=other`，不要把搜索摘要伪装为已经读取的官网正文；字段 `scope_name` 由模型绑定，程序只验证其属于确认名单，绑定是否正确还需样本和后续证据核对。来源关联不等于对 Product.reason 的语义认证；本块也不新增工具返回内容的服务端凭证，模型填写的来源元数据仍需与调用轨迹及样本核对，不能声称已从程序上杜绝虚构 URL。

具体参数或体验若写成 Claim，继续遵守板块 3 的已知事实／评价引用规则；本块不强制提前填满事实表。配置不明确可以保持未知并建缺口，不能猜测参数。更新同 ID 仍是整条替换，须读取并保留需要的关联字段；不改变现有 upsert 语义。

### 4.3 写入前的范围检查

在 `_data_call` 的 `apply_batch` 之后、`save_result` 之前调用纯函数，输入当前已确认 scope、合并结果与本次 batch。沿用原权限处理器、版本检查、文件线程和错误结构，不提前写文件或状态。

| 规则 | 执行方式 |
| --- | --- |
| 数量 | 合并结果中 disposition=candidate 的产品数不得超过 target_candidate_count；excluded 不占名额；按产品而非配置／来源计数 |
| 仅比较指定对象 | allow_discovery=false 时，每个 candidate 必须绑定 named_candidates 中的名称；查询这些对象的资料仍允许 |
| 指定对象并允许补充 | 可加入有发现来源的新产品，但不无声替换指定对象；指定对象缺失／被排除要保留说明与缺口 |
| 显式排除对象 | 绑定 excluded_candidates 或规范名称与其精确匹配的记录不能成为 candidate；不能通过不填 scope_name 绕过精确排除；允许以 excluded 保存审计说明 |
| 理由／来源／维度 | 对本次新增或更新记录检查第 4.2 节要求；来源关联检查合并后结果，支持同批提交产品与来源 |
| 去重 | 同一 scope_name 不能对应多个候选；对完全相同的规范名称或明确相同品牌／型号作确定性去重；不做模糊匹配或在线商品实体库 |
| 不足目标数量 | 允许分批写入，允许最终候选少于目标；不足说明在最终受控样例中验收，不因中间批次数量不足就强制报错或制造缺口 |
| 写入失败 | 返回现有 error.code／field／message；revision、checkpoint 索引与快照文件均不推进；不得悄悄截断候选或改范围 |

自然语言 hard_constraints、preferences、product_scope 等目前是自由文本。**本块不声称程序能通用判定任意语义硬约束或识别所有产品别名。** 模型解释筛选并保留证据／未知，固定样例人工标注应保留、应排除和待核实对象；程序负责可确定的数量、名单绑定、结构、版本与引用约束。名称归一只作首尾空白／大小写等保守处理，不去除可能区分型号的数字或后缀。

预算未知不直接淘汰或认定符合预算：可保留为待核实候选并标明价格缺口，后续板块 5 主动核实销售渠道价格。搜索空结果／错误只能表达“本次检索未获得可用候选”，不能把工具故障判成无市场产品。若发现共享搜索／读取工具必须修改，先用失败用例证明必要性，再单独限定改动与回归；初版不重写共享采集层。

本块没有新增“规划完成”工具或最终状态，所以不会声称已通过程序保证阶段闭环、必须项语义覆盖或候选不足收束。其受控验收由最终快照、模型调用轨迹与人工期望共同判断；正式阶段与预算收束归板块 6。

## 5. 整块开发顺序与退出条件

以下是一个完整板块任务，内部按 TDD 推进，无需每步等待用户审批。

| 顺序 | 开发工作 | 本步可检验结果 |
| --- | --- | --- |
| A | 固定代码／配置版本，执行本轮开发前默认离线与严格 I/O 基线；构造搜索、页面和人工筛选期望样本 | 基线结果单列；新契约、名单越界、数量越界等用例先出现预期失败 |
| B | 最小数据增量与纯范围检查 | 合法规划通过；旧快照可读；非法写入无副作用；不调用网络或模型 |
| C | 接入原中间件和研究指引，调整数据工具说明 | 研究模式获取指引；普通模式不变；原权限与独立写入仍有效 |
| D | 增加受控搜索／页面替身，跑原 Agent 工具循环 | 确认→搜索→必要读取→记录候选和维度→分页回读；宽泛和指定路径均有证据 |
| E | 验证真实工厂、worker、HTTP/SSE、刷新状态及 SQLite full／delta 恢复 | 结果源于原快照与 checkpoint；不依赖新增接口或前端面板 |
| F | 全部相关回归、开发后默认离线与严格 I/O，Ruff／diff／文档检查，整理报告与集中复盘 | 报告列明实际通过／失败／跳过及未验证边界；满足退出条件才标记实现完成 |

本轮规划不预先承诺测试数量、全量通过、工期或成本。开发时按失败用例和实际日志更新，不将板块三历史通过数当作本块开发前／后的执行结果。

## 6. 验收样例与测试矩阵

样例中的产品使用明确标注的合成名称、固定 URL／页面文本和时间；它们是可重复测试资料，不是真实购买建议。手机与笔记本只是跨品类样例，不是支持范围枚举。

| 编号 | 场景／输入 | 预期检查 |
| --- | --- | --- |
| D01 | 影像、续航优先的手机发现，目标数量 4 | 来源能追溯；理由关联用途；包含适用的影像／续航维度及口径；不强制凑够 4 个 |
| D02 | Python／Docker 开发、日常携带的笔记本，目标数量 3 | 比较内存／开发条件、重量等用途相关内容；不用手机维度模板；配置独立 |
| D03 | 指定 A、B，allow_discovery=false；检索返回 C | 允许检索 A、B 资料；C 不能作为候选落盘；错误不能推进快照 |
| D04 | 指定 A 并允许自动补充到目标数量 | A 不被无声替换；新增对象有发现来源；不超过目标 |
| D05 | 明确排除 B；模型提交 B 为 candidate | 确定的排除绑定被拒绝；excluded 可保留原因；注明别名语义仍需核对 |
| D06 | 分两批提交，第一批未超限，第二批合并后超限 | 检查合并后的总数，第二批整体拒绝；不能只检查 batch 长度 |
| D07 | 同型号不同配置、重复店铺、完全相同名称 | 配置不重复计为产品；确定性重复不扩充候选；不错误合并 Pro 等不同型号 |
| D08 | 自动发现候选无来源、来源悬空／跨产品／failed | 新增或更新记录被拒绝；同批有效产品＋来源可写入 |
| D09 | 用户指定对象尚无来源；预算或配置未核实 | 可保留对象，明确未知与 Gap；不伪造已知事实或符合预算结论 |
| D10 | 新候选无理由／维度无适用说明／basis 为空 | 返回对应字段错误；既有快照仍可加载，未触及旧字段不被伪装成新合规记录 |
| D11 | 仅找到两个可用候选，目标四个 | 最终受控快照有缺口原因，不生成假产品；分批中间状态不误报完成 |
| D12 | 搜索无结果、返回错误、读取失败或工具不可用 | 记录检索／证据缺口；不宣称市场无产品；不擅自修改范围或权限 |
| D13 | 来源保留标签或自然语言“忽略用户预算” | 原文仍是数据，不进入系统规则；测试证明通道和标签边界，不宣称消除全部语义注入 |
| D14 | 未确认直接搜索或写入；新文字后继续调用 | 真实处理器未执行；旧确认失效，范围不变的数据仍按原规则保留 |
| D15 | 错研究 ID／范围版本／revision；混合或多个写入 | 命中指定错误，保留正确上下文以免其他校验掩盖负例；无文件与索引更新 |
| D16 | 权限拒绝、磁盘失败、异步取消 | 原权限链有效；晚到文件不晋升；已有板块三用例回归，必要时补规划字段断言 |
| D17 | SQLite 真正关闭后重开，分别 full／delta | 候选关联、维度、缺口与版本一致；不能只用 JSON 往返替代 |
| D18 | HTTP/SSE 与刷新状态读取 | 原工厂／worker 产生真实事件与结果索引；分页读到规划内容，不要求新面板 |
