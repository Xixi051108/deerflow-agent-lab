# 板块五实施计划：证据采集、当前价格与事实核对

日期：2026-10-20。当前状态：**核心已实现，受控测试通过，真实电商追加验收未通过、待修复。** 见 [小米15实际验收](RESEARCH_EVIDENCE_WEB_ACCEPTANCE.md)。下文保留开发前任务书及当时基线；对应 [10 个板块计划](MODULE_PLAN.md) 的板块 5，不是需求文档历史五阶段草案的“校准与演示”。规划时核对工作区为 `main`、HEAD `0a8d5db`；板块四及专项修复仍有未提交文件，必须保留，以开发前实际工作树为基线。

## 1. 本块目标、前置状态与边界

将板块四的“候选与比较方案”推进成**有实际采集依据、配置与口径明确、能表达未知和冲突的事实集合**，供板块六的收束、板块七的分析与文件交付使用。

当前前置状态：

- 板块 1–4 已实现范围确认、原链路准入、数据快照、候选及维度规划，不重做这些模块。
- 交接顶部及 [板块四测试报告第 7 节](RESEARCH_DISCOVERY_TEST_REPORT.md#7-两项失败的专项修复2026-10-20用户追加要求) 是最新回归记录：默认离线 17,132 passed／357 skipped／0 failed，严格 I/O 148 passed／1 skipped。这是历史结果，不是本轮执行结果。
- 第四阶段真实 DeepSeek 使用冻结资料，暴露过理由数字幻觉、捏造用户要求和错误引用重试；最后三例通过，不能推导开放网络或当前价格已经核实。
- 沿用消费者选购优先、开放品类、确认后自动研究、公开来源、中国大陆／CNY／中文可修改默认值；普通新文字仍先重新确认，不增加逐阶段审批。

本块交付五项能力：

1. 区分搜索线索与已读取页面，保存实际采集文本、时间、状态及可追溯关联。
2. 对长页面、读取失败、限流、空内容及证据缺失作明确处理。
3. 从具体产品／配置的原文提取事实，保留单位、条件及评价与推断的区别。
4. 主动查询官网或京东等公开销售渠道，区分当前页面报价、历史价格及条件价。
5. 保留不同来源的说法、冲突与缺口，验证数据能够沿原链路落盘、恢复和回读。

本块不包含：业务级总时间／调用预算和重试调度（板块 6）、最终推荐与 Markdown／CSV（板块 7）、面板（板块 8）、完整开放网络任务的成本校准（板块 9）。市场分析专属指标和交付仍待该用途实施前细化。不得增加独立 FastAPI、Agent 循环、抓取平台、数据库、消息队列或强制多 Agent；不承诺登录后采集、绕过访问限制、实时库存或实际成交价。

| `community/jina_ai/tools.py::web_fetch_tool` | Jina HTML → Readability → Markdown 前 4096 字符；工具只返回字符串 | 研究采集复用底层客户端和提取器，取得有界正文与状态；不直接把通用工具输出调成巨量全文 |

重要区别：目前 Source 的 URL、标题、时间、正文及配置范围由模型提交，`quote in source.text` 只能证明两段提交文字相符。即使补一个由模型填写的哈希，也不能证明网页真的被读取。另一方面，真实读取了网页，也不能自动证明模型正确理解了商品配置、优惠条件或原文语义。

## 3. 建议实现：研究采集入口加原数据写入校验

### 3.1 复用边界与工具职责

优先新增一个研究专用采集入口，暂名 `collect_research_source`，复用 JinaClient 与 ReadabilityExtractor。它填补“真实读取与受控保存”缺口；既有 `record_research_data` 仍负责模型提取的事实／引用／缺口，不新增第二套事实写入 API。

建议参数包括 URL、已有 product_id、适用配置或 product_wide，以及当前研究／范围／数据预期版本。调用方不提供正文、采集时间、哈希、捕获凭据或文件路径。工具名和字段在首轮契约测试落实，以下职责作为实施要求：

- 调用先验证已确认范围、可信身份、目标记录及预期版本；通过原权限／guardrail 后才联网和写入，不能直接从外层中间件绕过 handler。
- URL 仅取用户提供或实际工具返回的公开 HTTP(S) 链接，延续原工具的使用范围；不猜商品地址，也不因新入口放宽原访问策略。异步网络保持异步，文件／同步提取使用现有线程边界；同步工具路径同样需有可运行的适配与回归，不能在事件循环线程直接阻塞或嵌套 asyncio.run。
- 产品和已知配置先通过原数据工具保存。采集是唯一的状态写入工具调用；同批采集与记录、多个采集或其他工具不得竞争更新 revision。沿用现有独立写入规则，不新增锁或执行器。
- 工具保存实际接收的有界文本、请求 URL、服务端采集时间、成功／截断／失败信息及采集关联，返回新 revision 和 Source IDs。标题缺失时明确缺失／使用可辨识占位，不能让模型编成原网页标题；发布时间只在可靠可得时填写。
- 来源类型和产品／配置适用范围可以由模型提出，但仍是待核对的归类。程序产生的采集记录不等于程序认证了官网身份、商品配置或卖家。
- 错版本、权限拒绝和非法目标在请求前阻止；网络失败可保存失败观察供回读。保存失败时不得谎报“已留证”，只返回原错误；取消或未提交 checkpoint 时不晋升晚到结果。
- 服务端产生的采集元数据与文本不可由普通批次伪造或改写。仅有 ID／哈希不作为凭证；校验当前研究里实际存在的受保护采集记录，并拒绝用省略新字段的整条替换绕过保护。

首次实现优先把采集片段保存到既有 sources 集合，继续使用原快照和分页。不引入独立证据数据库、签名体系或通用爬虫缓存。

### 3.2 长页面、容量与失败语义

推荐“一次有界读取，分段保存，多页回读”：

1. 对上游响应、提取后的正文和本次保存总量分别设工程上限；在读取边界执行限制，不能下载完整无界响应后才截断。复用现有客户端时必要的底层增量以失败测试约束，并保留通用工具兼容入口。
2. 单次读取所得文本按 Unicode 边界分段，每段作为一个 Source 记录，共享服务端采集组标识和 URL，保留区间／顺序。目标为单条序列化记录明显小于 16 KiB；建议先以 8 KiB 为记录预算，具体正文长度按 UTF-8 和 JSON 开销计算。
3. 使用现有 `read_research_data(section="sources", ...)` 阅读后续片段，不把全文一次灌进上下文。引用定位同时标识采集组／片段和精确摘录；分段不是多个独立来源，交叉核对不得据此增加来源数量。
4. 来源总长度上限和截断原因显式保存。到达工程上限后丢失的尾部属于未取得证据，不能称为已读全文。超过 2 MiB 快照上限仍拒绝保存；不静默抬高现有快照或分页阈值。
5. 对登录／验证码／空页面等，只记录实际返回状态和内容特征。“价格未在提取结果中出现”不等于页面没有价格；不能仅凭模型说明归因为反爬。商品页正文提取失败时保留失败／缺口，不扩展浏览器登录或自建商品 DOM 通用解析器。

新 Source 可选字段仅表达最小采集方式、组标识、片段位置及截断信息；旧数据缺省为 legacy／未绑定采集。对旧快照保持原字节、原哈希和可读性，不在 load 时强行升级。新写入事实与旧记录的判定分开：旧样本继续可读，新事实要求实际采集支持；旧搜索来源仍可作发现线索，不能因此取得“已读销售页面”资格。

搜索仍优先用现有 `web_search`。如为明确的失败处理而调整 DDG helper，则提供区分成功空结果与异常的内部结果，保留现有公开工具签名和兼容输出；覆盖共享调用方回归。当前价格采集成败不依赖预先重写全部搜索工具。

工程容量数值在实现前通过中文长页面、元数据和 JSON 转义样本确定并写入测试；这些是防止单次响应失控的技术限制，不是板块六的研究预算默认值。

### 3.3 事实提取与写入检查

建议新增 `research/evidence.py`，放可信静态采集指引和纯校验／评估函数；网络适配放 `research/collection.py`，仅在职责确实需要时拆分。继续调用 `validate_research_plan`，其后在 `save_result` 前检查证据，输入至少包括确认范围、旧结果、合并结果与本次批次。

| 内容 | 确定性规则 | 语义核对责任 |
| --- | --- | --- |
| 新已知事实／评价 | 保留现有引用、摘录、产品／配置和单位校验；本块新增事实需引用实际采集记录，不能仅引用模型自填正文 | 摘录是否真正支持数值、结论及适用配置，固定样本与人工审核 |
| 用户评价／独立评测 | 与 fact／inference 分开，保存样本与测试条件 | 不把少量评价推广为总体满意度，不把官方宣传当独立体验 |
| 未知 | value=null、missing_reason；关键缺口有 Gap | 缺的是哪个事实、为什么缺、会影响什么结论 |
| 单位 | 不同量纲拒绝；只对明确可换算的单位作小范围转换，保留原始值／单位和换算依据 | 不把 mAh 与 Wh、不同续航测试条件或不同规格口径强行等同 |
| 冲突 | 不同观察保留不同 Claim IDs；同一对象／配置／维度的可比较差异关联 Conflict | 区分真的矛盾与地区、条件、时间、配置差异；转载不算独立来源 |
| 推断 | 继续引用已有已知事实／评价，不伪装成来源原文 | 解释推断依据与限制，本块不提前生成最终购买推荐 |

同 ID upsert 现为整条替换，不在本块悄悄变成删除／审计平台。对会抹去已知不同观察的更新，首轮测试确定最小保护：要求另用 ID 保存并解释差异；允许的纠错必须有明确处理说明。已有不可变快照提供历史，不等于当前结果已保留冲突。本块不承诺任意自然语言冲突或所有错别名能被程序识别。

对于简单换算优先标准库 Decimal；不引入通用单位库、自动商品实体库或任意语言价格解析引擎。测试先覆盖确认的少数换算关系与拒绝规则，其他口径原样保留／单独比较。

### 3.4 当前价格判定：观察记录与可用性评估分开

继续使用现有 Price：amount、region、currency、channel、seller、basis、conditions、observed_at，以及明确 Configuration。保留 launch／list／public_offer／promotion／member／subsidized／used，不能将所有数值自动提升为当前到手价。

建议由纯函数派生“当前页面报价可用／条件价／历史或标价／未核实及原因”的评估，不增加 `verified=true`，不让模型直接填写程序核实结论。评估需结合来源采集方式、配置、范围地区币种、价格口径、采集时间及已明确的条件。程序只能校验可表达条件；文本支持性仍需审核。

本阶段价格流程：

1. 对已选候选的明确配置，主动检索官网商城、京东等公开销售渠道。优先官方销售渠道／平台自营；至少留下实际渠道查询／读取或工具不可用的证据，不能仅存旧发布稿后直接结束。
2. 页面必须支持对应型号、内存／存储等配置、金额、币种／地区、店铺身份和可见优惠条件。未明确的信息不能靠模型猜补。“起售价”不能替代指定配置价格，促销／会员／补贴资格不明不能当成人人可享。
3. 官网规格页可支持固定参数；旧发布稿可支持首发价；它们不能单独证明当前页面报价。搜索摘要、其他配置、价格区间或登录占位同样不足。
4. 采集时间来自服务器实际读取；`observed_at` 不可早于／晚于实际观察被任意填写，允许的时间关系在契约测试落实。发布时间、页面标价时点与采集时间分别表达，不将旧数据改成“今天的价格”。Jina 返回可能含缓存或旧页面，采集记录只证明本次取得了该响应；需结合页面时间／价格上下文，不能仅因工具今天执行就认定内容为今天有效报价。
5. 地区、币种与范围不一致时可保留为不适用的观察和缺口，不能直接用于预算符合性。型号配置不明保持未知，不把低配价格借给高配。二手价格只能按其口径记录。
6. 两个渠道当前报价不同可并存，带渠道和条件；只有相同可比较条件下矛盾才归为冲突。不要因为有两个不同报价就随意取最低或判一方错误。
7. 仍无足够证据时，保存 `value=null`／Gap，说明“当前价格未核实”及实际原因；仅有条件价时明确其条件，不能输出无条件到手价。何时因总预算停止补证由板块六落实，本块不声称能自主控制整项研究耗时。

“当前”只表示此次采集时公开页面展示的匹配报价，不保证实际库存、用户可享优惠、结算金额或未来价格。不拍脑袋统一规定所有产品的价格有效期；跨日恢复的数据不能无提示地冒充新采集，过期策略与业务时钟在板块六／九衔接。

## 4. 原链路中的业务顺序

确认范围 → 读取原候选与维度 → 必要时保存明确配置 → 搜索官方／评测／销售／评价来源 → 采集并保存实际页面 → 分页读取相关片段 → 提取事实与精确引用 → 对照配置、单位和价格条件 → 补证并保留冲突／缺口 → 独立批次写入 → 回读检查并说明本阶段结果。

这是原 Agent 内的业务顺序，不新增执行循环或阶段审批。研究静态指引需同步修改：保留板块四“先规划”和不猜数字的要求，删除“本阶段只能写规划集合”和“规划后结束”的限制。原规划功能仍可单独验收；既有 live 用例可通过自身任务只做规划，不能依赖系统指引永远禁止事实提取。

工具授权仍生效，缺读取能力不偷偷换用无授权通道。完整研究 phase／完成状态仍归板块六，本块沿用 awaiting_confirmation／recording；Run success 不能当作事实核对完成。

## 5. 整块实施顺序

下表按完整板块执行，内部逐项 TDD，不需要每写几行等待确认。先固定样本和预期，再改代码；不先把真实模型放到开放网络反复试错。

| 顺序 | 工作包 | 可检验产物 |
| --- | --- | --- |
| A | 固定当前工作树、执行开发前默认离线和严格 I/O；构造页面与人工事实期望 | 独立基线日志；旧正文截断、假来源支持价格、配置错配等首轮失败用例 |
| B | 最小来源采集契约与有界读取／分段保存 | 真实服务端时间和受保护采集字段；长页尾部证据可经原分页读到；失败不伪装成功 |
| C | 证据纯校验、价格评估、单位与冲突规则 | 同一套规则适用于手机和笔记本；历史／条件／未知价格均有明确结果 |
| D | 接入原工具集、中间件和静态指引 | 原权限链、确认、单写入规则有效；原工厂与内嵌客户端一致；普通 Agent 不变 |
| E | 脚本模型、真实工厂／worker、HTTP/SSE、SQLite full／delta 恢复 | 确认→规划→采集→事实写入→回读闭环，状态指针和实际文件一致 |
| F | 真实 DeepSeek＋冻结资料的受控质量验证 | 模型自主决定补查渠道与保留未知；逐项核对语义、配置、金额、条件、引用和实际轨迹 |
| G | 有上限的公开来源工具探测，再完成回归与报告 | 区分真实可达性与模型能力；相关回归、开发后两类全量、Ruff、文档和最终 diff 的实际结果 |

实施本块时不沿用历史全量数字冒充新基线，也不预先承诺测试数量、工期、成功率或 token 成本。若发现无关失败，保留原测试及日志，定位后单独说明，不删断言或加跳过换绿灯。

## 6. 验收矩阵

冻结样本使用明确标注的合成产品、固定时间与网页正文；当前价格正确答案仅针对样本，不构成真实购买建议。

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| E01 | 手机官方规格、匹配配置销售页、独立评测、少量用户评价 | 事实／评价／推断分开，来源、配置、条件和摘录正确，不推广样本评价 |
| E02 | Python／Docker 与便携笔记本，低配销售页＋高配评测 | 不混用配置；没有依据的性能／价格未知；维度仍随用途变化 |
| E03 | 旧发布稿先返回首发价，随后有匹配销售页 | Agent 主动补查销售渠道；历史价保留口径，当前报价另有实际采集证据 |
| E04 | 所有公开销售页均失败或要求登录 | 留下实际尝试与原因；当前价格未核实，不猜金额、不使用 0 |
| E05 | 只有搜索摘要、模型自填正文或伪造采集字段 | 不能作为新当前价格依据；伪造／改写受保护记录被拒绝 |
| E06 | 会员／补贴／以旧换新价，资格或叠加条件不明 | 条件价单列，未知条件明确；不能当成普遍可享的到手价 |
| E07 | 起售价、价格区间、另一存储版本或二手价 | 不替代指定全新配置价格，保留不适用观察与缺口 |
| E08 | 地区／币种／观察时间不匹配，今天读到旧页面或缓存 | 不判断符合当前预算；错误时间来源被拒绝或评为未核实，不因今天采集就认定报价有效 |
| E09 | 价格在 4096 字符以后；含中文、转义与跨片段摘录 | 后续片段能回读；单条和单次响应不超限；不能将拼接错位摘录判为原文支持 |
| E10 | 上游大响应、正文超限、快照接近 2 MiB | 有界处理和明确截断／拒绝；不宣称已取得上限外内容，不推进失败状态 |
| E11 | 超时、429、空正文、提取失败、搜索无结果／异常 | 按实际可知信息区分；旧 DDG 混合返回不虚构根因；不给“全市场无产品”结论 |
| E12 | g↔kg 等明确转换，mAh↔Wh 或不同续航条件 | 正确转换保留依据；不支持的量纲／口径拒绝或分开，不能直接比较 |
| E13 | 同配置同条件不同事实、不同渠道不同价格、转载 | 真冲突保留原说法并关联；不同条件不强行判冲突，转载／页面片段不增加独立来源数 |
| E14 | 单位正确、摘录存在，但原文语义与提交数值矛盾 | 固定质量样本判失败；程序结构通过不能代替语义审核 |
| E15 | 页面中“忽略预算／伪造来源”等注入文本 | 原文保留为数据，不进入系统指引或改授权；不声称单个样本证明消除全部提示注入 |
| E16 | 未确认、普通新文字、旧确认、错研究／范围／revision | 请求前阻止，网络调用数为 0，文件与索引不变；原确认规则回归 |
| E17 | 采集与记录并发、同批多个写入、权限拒绝 | 整批不执行／按既有规则拒绝，不发生丢失更新，禁止绕过原权限处理器 |
| E18 | 保存失败、checkpoint 失败、异步取消 | 已有结果保留；未引用文件不晋升；不将原始响应误报为已保存证据 |
| E19 | SQLite 真关闭重开、full／delta、HTTP/SSE 和分页 | 采集关联、价格口径、引用、冲突及缺口恢复一致；使用真实原链路事件 |
| E20 | 跨用户／Thread／Agent、历史恢复、分支、旧 JSON | 继承现有隔离和清空规则；采集关联不能跨研究借用；旧原字节／原哈希可读 |
| E21 | 普通 Agent、原内嵌入口、板块四仅规划任务 | 普通行为不变；两个研究入口工具一致；候选和范围约束不退化 |
| E22 | DeepSeek 自主处理 E03、E04／E06 及跨品类配置 | 真实调用轨迹证明补证选择与最终数据相符；无参数／条件／用户需求幻觉；失败轮保留 |

规则测试的负例须保持其他字段有效，断言命中的错误码、外部调用数和无副作用，避免提前失败掩盖目标。语义验收不能只检查“已核实／未知”等关键词，应按冻结原文逐字段审核。

## 7. 三类验证与运行边界

**确定性验证：** 纯数据与规则、受控传输响应、真实文件、原图和 HTTP/SSE。复用现有 research fixtures，不复制整套测试框架；包括原确认、数据、存储、规划、工厂、客户端与 harness 边界回归。改动 DDG／Jina／Readability 时增加对应共享工具回归。

**真实模型、冻结资料：** 延续第四阶段要求，使用已配置 DeepSeek 和实际研究中间件／工具图，替换网络传输为固定资料，让模型自主选择工具和提取内容。首批覆盖“旧价后找到销售报价”“条件不明或渠道失败”“笔记本配置错配”；每轮保留原始业务消息、调用、结果快照、耗时与 token，并人工核对。可以先沿用每例 10 次模型、12 次工具、180 秒、单请求 45 秒、供应商不自动重试的测试保护；若不足以覆盖新流程，先说明测量原因再调整测试保护，不能删除关键步骤凑通过。它不是业务预算，也不能证明真实站点可达。

**公开来源工具探测：** 开发后只做小规模、固定清单的官网规格页、公开销售页和评测页读取，直接验证本块采集入口；按测试工具尝试设置有限次数与超时，不运行无上限自主研究，不购买或登录。返回受限时保留结果并说明实际支持范围；真实网站失败不能由冻结资料通过抵消，也不能预设必须成功抓到京东。完整开放网络闭环及重复成本校准仍在板块 6、7 可靠后开展。规划阶段不调用模型、不读取密钥、不请求网站。

后端按 [开发指南](../../../backend/AGENTS.md) 在生产代码修改前后执行默认离线与严格 I/O 全量。Windows 沿用已有 backend 虚拟环境、`-B`／`PYTHONDONTWRITEBYTECODE=1`、UTF-8、已有 uv PATH，必要配置升级测试使用 `UV_NO_SYNC=1`；不恢复全局 Selector 事件循环覆盖、不关闭防护。GNU Make 不可用时执行等价 Python 命令；两分片收集错开，详见 [测试指南](../../../backend/tests/AGENTS.md)。

本块无前端业务改动时不新增 UI 测试。Ruff check／format、文档本地链接、指南继承链预算和最终 diff 必须检查；日志分别记录真实子进程退出码，跳过、环境错误和未执行项单列。测试记录建议保存在 `.deer-flow/local-dev/research-evidence-verification/`，每轮用不同前缀，不覆盖失败证据。
