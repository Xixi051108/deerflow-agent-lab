# 选购研究 Agent：首轮原能力基线

日期：2026-10-18。使用本机 DeerFlow、已有 DeepSeek Flash 和“思考”模式；未修改业务代码、系统提示词、工具实现或模型配置。任务中的 Docker 指购买用途，没有启动 Docker 构建。

本轮是少量探索性观察，包含明确提示后的补证实验；不是固定评测集、稳定性测试或改造前后对照。手机初问、手机补证、笔记本提示词和上下文不同，不能用它们的耗时或 token 直接比较品类效率。

### 笔记本可复现输入

> 我想在中国大陆购买一台全新国行笔记本，预算 6000–8000 元，主要用于 Python 开发、运行 Docker 和日常携带，不玩大型游戏。请先明确研究范围并让我确认，再自主发现和比较 3 款候选，不要把品类维度写死。
> 确认范围后，请结合官方参数、独立评测以及官网或京东等销售渠道的当前价格，解释各款的推荐理由、取舍和不适合谁。区分具体型号与配置、历史价格与当前价格，注明来源和查询时间；查不到可确认的当前价格就写“当前价格未核实”，不要推算到手价。
> 最终请提供中文对比结果，并生成可下载的 Markdown 报告和 CSV 对比表。

确认卡选择（由助手按本次测试样例填写，不是用户真实购买偏好）：

- 裸机含税到手价，不含延保与配件；预算以无需国补或会员资格的价格判断，其他优惠另列。
- 仅 Windows，Docker 走 WSL2；32GB+1TB 起；无需独显。
- 选择“14 寸均衡（1.4–1.6kg）”，补充文字允许 14–14.5 英寸。
- 官网、京东自营，无品牌限制。额外口径写入卡片唯一的自由文本字段，后续设计应提供语义合适的补充说明位置。

Agent 在确认草案中另提出实测续航 ≥8 小时、USB-C 充电等条件；确认卡包含内存 16GB 草案与 32GB 选项等不同默认值。最终研究应以确认后的值为准。本轮没有最终报告，尚不能验证条件合并及实际筛选是否正确。

确认过程中的人工／工具操作时间不计入正式研究耗时。研究运行一段时间后，助手宣布本次外部观察上限为 10 分钟，并在约 10 分钟时点击停止；后台结算耗时约 10 分 29 秒。这个上限是实验保护，不是 Agent 自主停止、运行超时功能、已校准产品预算或用户确认的通过阈值。无法从人工中止推断它继续运行后必然不会完成。

## 3. 已有能力与缺口

### 已观察到的能力

- 具备范围澄清卡、模型／工具循环、多轮检索和自然语言比较的基础链路。
- 明确提示后能将当前价格标为未知、将旧价单列，且能尝试官网／电商读取；这仅证明本次指令后的行为，不能证明默认每次都会执行。
- 笔记本检索涉及 CPU、内存、存储、重量、电池、接口与评测等品类信息；没有最终报告，因此不判定跨品类业务验收通过。
- 本次可从页面停止运行，后台最终为 `interrupted`；未测试取消的全部并发／重连边界。

### 需要开发或定位的缺口

| 缺口 | 现有证据 | 尚不能断言的原因 |
| --- | --- | --- |
| 事实和引用关联不够具体 | GT8 引用为 2025-10-21 发布稿；正文支持 7000mAh／100W 等固定规格，不能支持 2026-10-18 当前到手价区间 | 未逐项独立验证其他候选参数真假 |
| 价格补证未完成 | 官网／京东查询尝试后最终未知，且出现 Pro 页价格可读性探测 | 403 是来源站、抓取服务还是网络限制，动态加载是否主要原因，均需原始工具证据 |
| 缺少可验证的研究收束与部分交付 | 笔记本连续检索约 10 分钟，人工停止前未输出完整答案、Markdown 或 CSV；界面未见产物入口，常见用户线程根路径下未找到该 Thread 文件目录 | 尚未用固定模型响应复现循环，也未定位模型策略、中间件、抓取失败和上下文累积各占多少 |
| 消耗不透明 | 研究 Run 中间件消耗 194,372 tokens，UI 与后台计数存在差异 | 不能直接宣称是某个中间件的 bug 或承诺优化比例 |
| 口径确认存在歧义风险 | 确认卡草案与可选默认值不同；补充预算口径只能写在品牌自由文本字段 | 尚未验证最终确认值是否被错误解析或覆盖 |

价格回归应允许继续使用旧型号的固定规格资料，但当前价格必须主动查销售渠道。无法核实时披露缺口；不能以降价常识推算确定价格，也不能让一个来源为整段推荐中的所有事实背书。

## 4. 下一阶段建议

首轮基线观察到此收口，先不扩大品类或重复高消耗研究。沿原定小步带练顺序推进：

1. 从“研究范围与确认约束”开始，由用户先写预期与失败测试；补充来源／候选／时间或调用限制的表达，具体默认上限仍待校准，不把本次 10 分钟保护直接写成产品默认值。
2. 明确程序可检查的停止与交付规则：有限补证；达到限制时停止新检索；保留已验证事实、缺口和来源；为 Markdown／CSV 生成预留资源，无法完整比较时交付部分结果。
3. 用受控网页样本和模型替身复现“重复查询／价格取不到仍继续”的场景，再逐项核对真实工具结果，确定最小实现位置。提示词可指导研究，程序负责预算与数据约束。
4. 核心链路有确定性回归后再用相同小批真实任务复测，并保留失败与成本，不先添加浏览器抓取、新模型或多 Agent 编排。

这些是基于基线的实施建议，尚未编写业务实现或新自动化测试。
